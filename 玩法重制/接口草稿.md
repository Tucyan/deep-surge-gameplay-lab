# 接口 · 当前 v5 与历史草稿

更新：2026-10-07。本节对应 `src/core/` 已实现的 JavaScript 接口；文末历史草稿中的模块名与命令形状不能直接作为当前调用示例。内容契约 `gameplay-experiment-v5`，`schema:1`、`randomVersion:'xorshift32-v1'`；不同内容版本记录隔离，不跨 v4 继续。

## v5 会话与命令

```js
session.getView()                  // 状态副本与公开界面投影
session.preview(command)           // {ok, errors}；在恢复副本中执行，不提交随机或费用
session.execute(command)           // {ok, errors, view, events}；events当前为空数组，日志在view.log
session.serialize()               // {schema, contentVersion, randomVersion, profile, state}
GameSession.restore(saved)        // 校验版本与状态后恢复，不发新涌泉

{ type: 'NewGame', seed, originId }
{ type: 'SubmitVoyage', nodeId }    // nodeId使用公开候选id（候选实例ID）
{ type: 'ScoutNode', candidateId, method: 'sanity' } // 或method:'relic'
{ type: 'FixHeading', method: 'wood' }              // 或method:'relic'
{ type: 'ChooseOption', optionId, cardId, equipmentId, enchant, relicId, protectedCardId }
{ type: 'ClaimRelic', accept: true, relicId }       // 拒绝用accept:false，不重抽
{ type: 'PlayCard', cardId, targetId }
{ type: 'ShopBuy', itemId, payment: 'coin' }        // 或payment:'corpse'
{ type: 'EndVoyage' }
{ type: 'EndBattleTurn' }
{ type: 'DiscardCards', cardIds }
{ type: 'FinishDiscard' }
```

`ChooseOption`可选字段按选项填写：兑换/附魔用`cardId`，免费升级用`equipmentId`，附魔用`enchant:'return'|'instant'`，祭坛用`relicId`，随机失牌保护用`protectedCardId`。它们是目标或奖励引用，不能当作通用费用列表。选项从当前节点实例读取，不能用全局静态表覆盖固定变体。普通木筏命令仍为`Craft`、`ExpandRaft`、`RepairCell`、`UpgradeEquipment`、`ActivateEquipment`、`FuelLamp`。

成功命令一次提交状态及随机进度；失败返回`ok:false`并恢复原状态与随机流。预览只保证可执行性，不额外返回概率计划；费用与概率由视图的`optionStatus`提供。玩法推进不依赖动画结束。

## v5 数据与视图

| 对象/字段 | 当前形状与边界 |
| --- | --- |
| `CONFIG.layers` | `[{id,name,bossNodeId,minVoyages?,maxVoyages?}]`；省略范围沿用全局默认。ID/名称为中性配置，不绑定海域主题 |
| 运行层 | `layers:[{definitionId,length,completed}]`；`layerIndex`从0计，`layerVoyage`从1计，`voyage`全局计数，`length`当前层长度 |
| `view.layer` | `{index,name,total,voyage,length}`；默认只有一层，双层仅测试配置验证 |
| 补给与导航 | `springClaimedVoyage`防重复领取；`navigation.fixedHeading`及计划/实际到达记录属于本次导航 |
| `view.candidates` | 公共`id`为不泄露定义的候选实例ID，`visibility:'full'|'detailsHidden'|'typeOnly'|'unknown'`；完整候选才有`definitionId`、选项、怪物和费用 |
| 池 | 存档仍保存可重复的`state.nodePool`；视图删除此数组，仅有`nodePoolCount`，界面不能用池推断隐藏内容 |
| `optionStatus` | 选项ID映射`{canChoose,reason,summary,probability,risk}`；正常候选按启航时AP与当前手牌检查，当前节点按真实AP检查 |
| `navigationActions` | `scout.sanity/relic`、`fixHeading.wood/relic`，各为`{canChoose,reason,summary}` |
| 祭坛节点视图 | `node.altarChoices`为完整奖励定义；`node.sacrificeCandidates`是合法手牌及数量；`node.detachableCells`含合法格及设备信息 |
| `pendingRelic` | 存档`{choices:[relicId],source}`；视图`choices`展开为`[{id,...definition}]`，领取或拒绝前阻止其他行动，放弃本局除外 |
| `relicUsage` | `scout:{charges,settlements}`、`heading/protect:{remaining,layerIndex}`，以及修理/回收/契印/逆流已触发航次等记录 |
| 环境实例 | `definitionId,remaining,activeFrom`及来源；节点获得时下一轮生效，同种刷新可有`pendingRefresh`，战斗不推进覆盖次数 |
| `sanityForecast` | 当前设备、燃料、状态和出身条件下的结算后SAN预测数值，不提前消费燃料 |

隐藏投影严格分级：详情遮蔽仅保留名字/类型；类型遮蔽不带真实名字、敌人、选项；未知不带真实类型。到达后揭示完整节点。候选固定生成，侦察只揭示、不重抽。Boss固定层末并公开；迷雾Ⅲ池内存在非战斗路径时提供可辨认的非战斗候选，不额外补池。

## v5 选项费用与生命周期

`OptionDef.cost`为AP，`cardCosts`为定义ID到正整数数量，`statCosts`为主动HP/SAN价格，`randomCardCost`为失去的合格实体单位数，`detachCell:true`为立即随机脱落合法外围格。结果可有固定`effects`、加权`outcomes`，藏品概率使用`relicProbability`和`successCondition:{stat,operator:'gt',value}`；概率读取支付前数值。费用、目标、合法随机池检查失败时完整回滚，不能用奖励倒付费用。

主动HP/SAN价格完整支付且至少剩1，使用`reason:'price'`区别于可减免的事件/航耗损失。记名绳结只保护一个实体单位，保护后其他单位仍足够付费，成功才消耗额度。立即脱落与普通破损不同：设备一并移除，不允许毁最后一格或断开剩余格。普通免费休整没有这些费用，升级/附魔仅要求合法目标。

新轮次由`beginRound`共用：激活待生效环境、判轮初环境、自动涌泉、固定候选。`SubmitVoyage`不发牌，混乱只从本次其他候选选实际到达点，并消耗该节点一份、记录访问、刷新一次基地AP。`EndVoyage`按有序步骤结算后进入`discard`；`FinishDiscard`校验容量后推进本层航次，或完成本层/跨层。跨层保留资源与木筏，重建层池/历史、重置已持有的每层额度，末层结束。

恢复校验包含层定义/长度/完成标记、全局航次一致性、涌泉领取记录、候选可见性、待领取奖励和藏品使用次数。存档保存固定随机算法和状态，读档不补充机会、不重复结算。

## 历史接口草稿（设计依据）

配套：[系统分层](系统分层.md) · [玩法](玩法.md) · [待完善](玩法待完善.md)。以下保留当时简写的数据形状，历史命令例子不能直接调用当前程序；实际接口以上面的 v5 段落为准，不要求新增工具链。

## 数据约定

定义ID表示一种内容；实例ID表示本局具体的一张牌或一个Buff。同名牌可有不同附魔与来源，不能只按名称记录。

| 对象 | 最少字段 |
|---|---|
| CardDef 卡牌定义 | id、类别、目标要求、条件、费用、效果、触发规则 |
| OriginDef / RelicDef 出身/藏品 | id、属性加成、效果修正、触发规则；藏品另有本局/永久标记 |
| BuffDef 增减益定义 | id、正向/负向、属性加成、效果修正、触发规则、叠加方式、计时时钟 |
| NodeDef 节点 | id、节点类型、options |
| OptionDef 选项 | id、条件、费用、结果列表（权重＋效果） |
| SettlementDef 结算 | id、时钟、按顺序排列的步骤 |
| CardInstance 卡牌实例 | instanceId、definitionId、位置、来源、附魔 |
| BuffInstance 增减益实例 | instanceId、definitionId、来源、目标、层数、剩余时长 |
| RunState 本局状态 | 阶段、航行/战斗计数、结算进度、基础属性、当前数值、卡牌、出身、藏品、Buff、木筏、节点、随机状态、版本 |
| Profile 局外档案 | 点数、永久解锁、珍稀藏品、科技节点 |

Buff的叠加方式可选替换、续时或加层，具体内容必须指定；期限明确属于航行轮、战斗回合或本场战斗。刚施加与到期时点由结算配置决定。

## 通用效果

每项效果都带 `sourceId`（来源实例）、`targetId`（目标）、`reason`（原因）。

| 效果 | 参数示例 | 用途 |
|---|---|---|
| ChangeCurrent | stat: hunger, delta: -30 | 饥渴消耗、回复、伤害 |
| GiveCard / RemoveCard | definitionId / instanceId | 获得或消耗具体手牌 |
| AddBuff / RemoveBuff | definitionId / instanceId | 添加或移除增减益 |
| GrantRelic | definitionId | 获得藏品，再由属性计算读取其效果 |
| SetFlag | key、value | 剧情、结局条件和解锁标记 |
| StartBattle | encounterId | 节点进入战斗 |

例：当前v3试测淡水牌输出“水分+40”；航行规则输出“饱食−30、水分−30”。两者共用ChangeCurrent，区别在来源、原因与触发时机。

## 对外接口

```js
session.getView()                  // 返回只读界面数据
session.preview(command)           // 可否操作、费用、确定效果或结果概率
session.execute(command)           // 实际执行，返回结果

// 命令例子：操作都使用实例ID
{ type: 'PlayCard', cardId, targetIds }
{ type: 'ChooseOption', nodeInstanceId, optionId, cardIds }
{ type: 'EndVoyage' }
{ type: 'EndBattleTurn' }
{ type: 'DiscardCards', cardIds }

// 执行结果
{ ok, errors, view, events }
```

事件仅供界面展示，如“水分减少30”“获得淡水”。规则通过统一处理器推进，不依赖动画结束或界面事件修改状态。

## 内部接口

| 模块接口 | 输入 → 输出 |
|---|---|
| CardRules.plan | 状态、出牌命令 → 条件、费用、效果 |
| NodeRules.plan | 状态、选项命令 → 条件、费用、候选结果 |
| SourceRules.collect | 状态、局外档案、时机 → 当前有效的加成与规则 |
| StatRules.get | 状态、目标、属性 → 基础值、加成明细、最终值 |
| TurnRules.plan | 状态、时钟 → 本次结算编号和步骤 |
| SurvivalRules.evaluate | 状态、配置 → 饥渴处罚或败亡结果 |
| BuffRules.tick | 状态、时钟、结算阶段 → 计时变化和到期移除 |
| EffectResolver.resolve | 状态、费用、效果/候选结果 → 新状态、变化记录 |

以上模块先返回计划；只有会话入口提交新状态。出身、藏品、Buff都由SourceRules收集，卡牌规则不需要逐个判断藏品名称。

## 执行约定

1. 校验阶段、目标、条件与费用；失败不扣费。
2. 在状态副本中支付费用；若代价已导致败亡则停止奖励，否则确定随机结果，再按顺序执行效果。
3. 每个效果先处理匹配的减损/免疫，再更新数值并检查败亡；败亡停止后续奖励。
4. 成功后一次提交状态与随机进度。预览、取消、拒绝操作不推进随机；随机状态随存档保存。

以上是接口草案的处理顺序；遗迹失败保护、燃灯时点等例外须先补完玩法，再配置对应步骤。不可把缺失规则当作0费用或默认奖励。

## 2026-10-05 已实现增量

OptionDef.cardCosts为卡牌定义ID到正整数数量的费用映射，cost为AP费用。RunState.nodePool为允许重复的节点ID数组，nodeVisits和lastNodeId记录本局选择。SubmitVoyage只消耗一份对应普通节点；ChooseOption先扣完整费用再执行奖励，特殊目标非法时完整回滚。详细行为和版本见 [节点投入与海域池](节点投入与海域池.md)。

## v3 试测契约

CONFIG.nodePoolMultiplier 为1～10整数，默认2；种子生成 (length−1) × 倍数份普通节点。存档仍保存剩余nodePool，恢复校验以该倍数计算初始上限，候选与历史规则见 [海域池](节点投入与海域池.md)。

EQUIPMENT.medkit.activationCosts 可配置基础资源数量；默认 {cloth:1}，每次ActivateEquipment先检查可用包扎包、未满血与材料，再扣1AP、材料并按等级治疗。费用不算打出，不触发回牌；缺料/AP不足完整回滚；preview不扣费。省略该字段表示该自定义配置不收耗材，不能配置到其他设备；复制包扎包为普通生产设备时清除此字段。治疗界面展示费用与持有量。

内容契约gameplay-experiment-v3；schema1、xorshift32-v1不变。旧版本航行记录隔离保留，不能跨规则继续。

## v4 历史契约

EndBattleTurn 不检查手牌容量，战斗及战后行动允许超限；仅 EndVoyage 进入 discard，DiscardCards/FinishDiscard 只接受 discard 阶段。去掉 battleDiscard 状态；当时内容契约 gameplay-experiment-v4，其他 v3 池与治疗参数保持。ShopBuy 不耗 AP，交易窗口按只读视图的优惠价显示币/尸体费用，关闭窗口不会执行离店选项。这些弃牌/商店行为在 v5 保留；详见 [历史说明](商店与轮末弃牌.md)。
