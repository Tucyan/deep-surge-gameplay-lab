# 系统分层 · v5 运行边界

更新：2026-10-07。当前运行代码为独立 JavaScript ES Module；不依赖 DOM、Three.js、动画或浏览器存储。界面通过 `GameSession` 命令与只读视图接入。以下模块表是实际职责，文末原分层草稿仅保留设计依据。

| 模块 | 当前职责 |
| --- | --- |
| `src/content/` | 纯数据定义，规则数值、层配置、环境权重、节点变体、藏品mechanic；不保存运行对象 |
| `core/session.js` | 会话入口、命令事务、预览副本、序列化/恢复校验、公开视图投影 |
| `core/layers.js` | 中性层定义、种子确定层长度、层进度校验、跨层选择；不硬编码海域/时间主题 |
| `core/nodes.js` | 池与固定节点实例、先涌泉的轮次初始化、实际到达消耗、节点选择和商店 |
| `core/node-costs.js` | 主动价格、实际概率、可支付摘要、随机实体单位失牌、合法外围格脱落 |
| `core/environment.js` | 环境兼容/上限、延后生效、实际覆盖计时、迷雾、偏航及导航操作 |
| `core/relic-rules.js` | mechanic能力查询、固定奖励、待领取/拒绝、充能、每层次数与每轮触发记录 |
| `core/raft.js` / `battle.js` | 木筏与航行结算；独立战斗回合与伤害、战后返回 |
| `core/model.js` / `effects.js` | 状态与属性、固定随机流、统一效果上下文、当前值变化和来源 |
| `src/ui/` | 只渲染公开候选、费用/目标/风险、层进度与奖励；不读隐藏定义推断遭遇 |
| `src/config/` / `src/editor/` | 默认/个人配置、校验与数据编辑；不能通过配置执行脚本 |

层定义在 `CONFIG.layers`，运行层为 `layers[{definitionId,length,completed}]`，`layerIndex`从0计、`layerVoyage`从1计，`voyage`为全局航次，`length`为当前层长度。各层末站首领由引用决定；胜利结算弃牌后跨层保留资源与木筏，重建池和访问历史。默认一层，双层只是测试配置，不代表第二层内容完成。

两类时钟独立。新轮初始化依次激活待生效环境、抽轮初环境、领取一次涌泉、生成固定候选；导航成功才刷新基地AP。结束航行先航耗、燃灯、生存检查，再老化、生产、时钟与弃牌。环境节点效果以 `activeFrom` 指向下一轮；战斗不消耗环境覆盖次数。`settledVoyage`、`springClaimedVoyage`、藏品使用记录和固定随机状态保证读档、取消、失败不重复领取或重掷。

`getView`移除`nodePool`，只返回`nodePoolCount`；隐藏候选不携带定义ID、真实名字、敌人、选项或费用。SAN/HP主动价格走完整支付路径，与可减免的非自愿损失分开。随机失牌与筏格脱落先检查合法对象，在事务内付完整费用后给奖励；非法目标使状态与随机流完整回滚。

随机藏品机会通过 `pendingRelic` 保留固定奖励，领取/拒绝前禁止其他局内行动（放弃本局除外）。祭坛在支付前选定奖励，次数与随机对象属于本局状态，不能交给弹窗或动画决定。机制能力按 `mechanic` 查询，藏品定义ID用于引用；八件新普通藏品不变为永久成长。

## 原分层草稿（历史依据）

配套：[玩法](玩法.md) · [待完善](玩法待完善.md) · [接口草稿](接口草稿.md)。以下抽象描述为历史设计依据，实际模块名、时点和接口以本文 v5 段落及运行代码为准。

## 四层结构

| 层 | 放什么 | 负责什么 |
|---|---|---|
| 内容定义 | 卡牌、出身、藏品、Buff、节点、结算规则 | 配置名称、条件、费用、效果；纯数据 |
| 游戏状态 | 当前生命、手牌实例、已获藏品、Buff、回合、随机状态 | 保存本局发生了什么；可存成JSON |
| 规则处理 | 出牌、选择节点、结算、属性计算、生存检查 | 读定义和状态，算结果；统一提交状态变更 |
| 界面表现 | 手牌、木筏模型、按钮、动画 | 展示只读结果，发送操作 |

调用顺序：界面发命令 → 检查条件和费用 → 生成效果 → 统一处理 → 返回新视图与变化记录。

## 各部分的边界

| 部分 | 自己负责 | 如何连接其他部分 |
|---|---|---|
| 卡牌 | 使用条件、费用、目标、打出/留手效果 | 输出通用效果，不直接修改生存或Buff状态 |
| 出身 | 开局选择与长期特性 | 提供属性加成、效果修正规则或触发效果 |
| 藏品 | 获得、失去、本局/永久归属 | 使用与出身相同的效果结构，不单写一套加成逻辑 |
| 属性 | 基础值、最终上限、当前值 | 汇总所有有效来源的加成 |
| Buff | 正负效果、层数、期限、来源 | 提供加成或触发效果；到期撤除自身贡献 |
| 节点 | 选项、条件、费用、结果 | 选项输出效果；随机结果由统一随机源决定 |
| 回合结算 | 触发时点、执行顺序、防止重复结算 | 调用对应规则，不写死“每轮扣多少” |
| 生存 | 饥渴耗损、归零处罚、败亡判断 | 耗损读配置；通过通用效果改变当前值 |

## 共用三种数据

| 数据 | 用途 | 例子 |
|---|---|---|
| 属性加成 Modifier | 改变上限或能力值，来源失效后撤除 | 出身使HP上限+10；藏品使手牌上限+1 |
| 即时效果 Effect | 执行一次并留下结果 | 水分−30、获得卡牌、添加Buff、解锁结局标记 |
| 触发规则 Rule | 到时机且满足条件才执行效果 | 航行结束扣饥渴；负面牌留手时触发惩罚 |

减伤和免疫在即时效果生效前处理，按来源和原因匹配。例如“事件精神损失减少5”只修改对应损失，不改变精神值上限，也不变成治疗。

## 数值与来源

- 当前值与上限分开：当前HP=20，不代表基础HP上限=20。
- 最终属性＝基础值＋有效加成之和。草稿先支持固定加减；上限提高不自动回血，上限降低时截断超出当前值。
- 每项效果记录来源实例、目标、原因；可解释“这1点AP来自哪个藏品”。移除来源只移除其贡献，不扣回已产生的物资或治疗。
- 基地AP与战斗AP分开；某个出身影响哪一种，由内容明确指定，未定时不默认两者都加。
- 永久解锁保存在局外档案，本局藏品与Buff保存在局内状态。

## 两种回合

| 时钟 | 触发示例 |
|---|---|
| 航行轮 | 固定饥渴消耗、设施生产、航行Buff计时、轮末弃牌 |
| 战斗回合 | 发箭、战斗Buff计时、留手负面牌惩罚 |

结算步骤用有序配置排列；燃灯与精神值归零等未定顺序继续记入待完善。每次结算记录唯一编号及进度，弃牌后继续流程不重复扣饥渴或发产物。

## 修改时改哪里

| 想改的内容 | 修改位置 |
|---|---|
| 饱食每轮−30改为−25 | 航行结算配置 |
| 新增一种回复牌、藏品或节点选项 | 对应内容定义，复用效果 |
| 新增一种此前没有的行为 | 增加一个效果处理器 |
| 调整卡牌外观或木筏动画 | 界面表现层 |
